# Adversarial review findings

## Blockers

**1. [engmath + tabular, BLOCKER] `load_matrix` interface contradiction.** Stats spec (the owner): `load_matrix(path, columns=None, key=None, cache_dir=None) -> tuple[np.ndarray, list[str]]`. Engmath's `linear_algebra` consumes `tabular.load_matrix(path, key)` as if it returns a bare `np.ndarray`, and additionally expects a `.json` **list-of-lists** shape that the owner's JSON dispatch (list-of-numbers / list-of-records / column-dict) explicitly does not accept. Fix: engmath uses `x, _names = load_matrix(...)`; add JSON shape (d) "list of equal-length numeric lists → matrix with synthetic col names" to the tabular spec, or restrict `matrix_path` to .csv/.npz and say so in the docstring.

**2. [systems + engmath + tabular, BLOCKER] dt is unobtainable through the loader everyone was told to use.** `load_series` returns a bare `(n,) ndarray`. Systems (`lti_response` custom input, `sampling_check`, `convolve_signals`) and engmath (`fourier_series`) all say "dt from the file", and the reserved-npz-`dt`-key convention is only a *request* in the math packs' §3 — it does not exist in the owner's tabular spec, and CSV/JSON have no dt channel at all. Fix: the tabular spec must gain an explicit surface, e.g. `load_series_with_meta(path, ...) -> tuple[np.ndarray, float | None]` (npz reserved key `dt`, `.ply` → `signal.dt`, csv/json → `None`), and every dt-consuming tool must error with "this format carries no dt — pass dt=" when it gets `None`.

**3. [engmath, BLOCKER] `parse_expr(..., global_dict={})` does not work — the "load-bearing" claim is wrong.** sympy's `auto_symbol`/`auto_number` transformations rewrite the token stream into code referencing `Symbol(...)`, `Integer(...)`, `Float(...)`; `eval_expr` then evaluates that code against `global_dict`/`local_dict`. With `global_dict={}` and none of those constructors in the WHITELIST local dict, parsing even `"2*x"` raises `NameError: Integer`. Every engmath test would fail on the first parse. Fix: eval namespace = `{"Symbol": Symbol, "Integer": Integer, "Float": Float, "Rational": Rational}` merged into `global_dict` (kept **out** of the user-facing whitelist hint); keep `local_dict` = WHITELIST + declared symbols.

**4. [stats + tabular, BLOCKER] `n_dropped_nan` cannot be produced from the spec'd loader.** `DescribeReport`/`FitDistributionReport`/`HypothesisTestReport` all require `n_dropped_nan`, but `load_series(dropna=True)` returns only the cleaned array — the drop count is thrown away inside the module the stats pack itself owns. Fix: `load_series` returns `(arr, n_dropped)` (or grows a `SeriesLoad` dataclass), or the stats tools load via `load_table` + `drop_nan_rows` (which does return the count) — pick one and write it into §0.2.

**5. [os, BLOCKER] Banker's golden sequence contradicts the stated scan rule.** "Repeatedly sweep P0..Pn-1, run the *first* process whose need ≤ work" (restart-after-grant) yields **[P1, P3, P0, P2, P4]** on the canonical instance: after P1 and P3, work = [7,4,3] and P0's need [7,4,3] qualifies before P4. The golden `[P1,P3,P4,P0,P2]` only falls out of *continue-the-sweep-within-a-pass* semantics. Test 12 fails as written. Fix: define the scan as "single pass P0..Pn-1, granting and continuing within the pass; repeat passes until no grant" — that reproduces the textbook sequence — and reword the design's rule text to match.

## Major

**6. [stats, MAJOR] `compare_dump_ripples` sector pairing is statistically invalid twice over.** (a) `sector_profiles` (transforms.py:192) silently **drops** empty sectors and returns a bare `list[Signal1D]` with no sector identity — positional pairing of `sectors_a[k]` with `sectors_b[k]` misaligns as soon as either side drops a wedge. (b) `fit_axis` sets `u = vt[1]` with no angular canonicalization, so θ=0 is an arbitrary direction *per dump* — sector k of dump A does not correspond angularly to sector k of dump B even at equal counts. The paired Wilcoxon is pairing noise. Fix: add a variant returning `list[tuple[int, Signal1D]]` (sector index kept), pair only shared indices; and for cross-dump comparison either reuse side A's fitted frame for both point sets (valid when comparing the same joint) or downgrade to an unpaired test (`mannwhitneyu`) with the docstring saying why.

**7. [ml, MAJOR — security] `predict(model_path=...)` is arbitrary code execution by design.** joblib deserialization executes pickled code; the only mitigation is an llms.txt sentence, which is advice, not enforcement, and the tool accepts any path (general-purpose inputs make this reachable from any client). Fix: `Path(model_path).resolve()` must be inside `ctx.models_dir` (or `data/`), AND the `.meta.json` sidecar this server wrote must exist next to it; otherwise ToolError listing `data/models/` contents. Cheap, preserves the round-trip test.

**8. [engmath, MAJOR — security/DoS] The parse gates don't stop evaluation-time blowups.** `9**9**9**9` (11 chars, passes every gate) and `gamma(10**7)` (gamma of an Integer evaluates to an exact factorial) hang or OOM the server at `parse_expr`/`doit` time — the 800-char cap and the "mode=numeric escape hatch" don't help because the hang happens before any mode logic. Fix: token-gate integer literals (reject any bare integer > 1e6 and any `**` whose right operand is itself a `**` chain or > 64), and evaluate `gamma`/`factorial`-family calls only via `evalf` on float args.

**9. [netqueue, MAJOR — constraint] 2 tools violates the locked "3-6 tools per pack is a HARD constraint".** The design's "(mini-pack scope approved at 1–2)" does not appear in the locked decisions, which name netqueue a "queueing mini" but state the 3-6 floor without exceptions. Fix: get the exception in writing from the user, or add a third genuinely useful tool (e.g. `mg1_calc` with a squared-CV parameter — the general P-K formula, of which M/D/1 becomes a special case, killing the `md1` mode too), or merge netqueue+os into one "sysmodels" pack (5 tools).

**10. [os, MAJOR] RR test contradicts the segment-merging rule.** With `ScheduleResult.segments` "merged consecutive same-name", the classic RR q=4 run is `P1[0-4) P2[4-7) P3[7-10) P1[10-30)` — P1 has **2** gantt slices, not the asserted 6 (after t=10 P1 is alone; its quantum expirations re-enqueue only itself, so the slices are contiguous and merge). Fix: assert 2 segments, or drop merging (then fix test 1's FCFS gantt string expectations accordingly).

**11. [imaging, MAJOR] Butterworth test number contradicts the tool's own transfer function.** Spec: `H = 1/(1+(D/D0)^(2·order))` (the Gonzalez-Woods convention). At D/D0=3, order=2 that is 1/82 ≈ 0.012 — attenuation ~82×. Test 6 asserts "≥ 8×, theoretical |H| = 1/√82 ≈ 0.11", which is the *other* convention (`1/sqrt(1+(D/D0)^{2n})`). Fix: keep the G&W formula and assert attenuation ≥ 50×; delete the 1/√82 note.

**12. [engmath, MAJOR] `linear_algebra` returns unbounded inline arrays.** `solution: list[float]` has no size cap — `op="solve"` on a 20 000-row least-squares file puts a 20 000-element list across the MCP boundary, violating the arrays-stay-on-disk rule the same report already honors for eigenvectors. Fix: inline `solution` only for n ≤ 64 (mirroring the n ≤ 12 eigenvalue rule); larger goes npz-only with `arrays_path`.

**13. [ml + tabular, MAJOR] `cluster`'s `vertex_index` passthrough has no data path.** `tabular.load_matrix` returns `(X, names)` only; the promised `vertex_index` passthrough into `clusters_*.npz` can't come from it. Fix: specify that `cluster` re-opens the source `.npz` itself to copy `vertex_index`/`dominant_joint` when present (one sentence), or extend `load_matrix` to return an extras dict — currently the implementer must invent an interface.

**14. [systems, MAJOR] `sampling_check` silently returns "safe" when it cannot see above the proposed Nyquist.** If `fs/2` is at or beyond the loaded signal's own Nyquist (0.5/dt), `energy_fraction_above_nyquist` is structurally ~0 and the verdict is a false "safe". Fix: guard `nyquist >= 0.9 * (0.5/dt)` → ToolError (or verdict `"insufficient_resolution"`) telling the caller the reference signal must be sampled well above the proposed rate.

**15. [stats/ml vs imaging vs engmath/systems, MAJOR — cross-pack contradiction] Three different conventions for new output dirs.** Stats/ml *modify the frozen `AppContext`* (add `models_dir` — a frozen dataclass whose manual constructions in tests would all break on a new required field), imaging explicitly refuses to touch AppContext and uses a pack-local `_images_dir(ctx)`, engmath/systems create `ctx.data_dir / "series"` in the toolset. Fix: standardize on the imaging pattern (pack-local `mkdir` helper off `ctx.data_dir`) for `models/`, `series/`, `images/`; no AppContext change anywhere. If AppContext is ever extended, the new field needs a default.

## Minor

**16. [stats, minor] `_round_floats` extension is incomplete for the new schemas.** The proposal covers dict *values* that are floats, but `confusion_matrix: list[list[int]]` is fine while `eigenvalues: list[list[float]]` (engmath) and `top_loadings: dict[str, dict[str, float]]` (ml) are nested one level deeper than either branch reaches (current validator, schemas.py:32-39, handles only float and flat list). Fix: make the validator recurse into lists-of-lists and dict-of-dicts; verified safe for `engine_stale` (it carries ISO strings, not float mtimes — engine_cli.py:305-311).

**17. [all packs, minor] llms.txt rule numbers collide three ways** (stats claims 12; engmath 12-13; systems 13; imaging 12; netqueue 13; os 14). Every design defers "coordinate at implementation time" — nobody owns it. Fix now, in order of locked decision 1: stats=12, imaging=13, engmath=14, systems=15, ml=16, netqueue=17, os=18; whichever pack lands first also rewrites rule 11's "Six MCP tools" sentence to "Tool packs (see README table)".

**18. [ml, minor] Deliverables written into the PLY parse cache.** `features_*.npz`, `clusters_*.npz`, `predictions_*.npz` go to `data/cache/`, which `ply.load_dump_cached` treats as its sha1-keyed cache (ply.py:230). No collision in practice, but user-facing artifacts don't belong in a cache the reasonable move is to wipe. Fix: put them under `data/series/` (already the engmath/systems convention) or a new `data/features/`.

**19. [tabular, minor] Size limits are MCP-hostile.** `genfromtxt` on a 400 MB CSV / 5e7 cells takes minutes inside a synchronous tool call (the repo's own llms rule 10 exists because long calls blow MCP timeouts). Fix: default `MAX_FILE_BYTES` ≈ 64 MB, `MAX_CELLS` ≈ 5e6; both stay module constants for monkeypatching.

**20. [stats, minor] `describe` on `.ply` reports CIs over 256 interpolated bin medians, not vertices** — `n=256` regardless of mesh size, and the t-interval treats binned medians as iid samples. Fix: docstring + a report `source` note ("n = axial profile samples, not vertices"); don't pretend vertex-level inference.

**21. [stats, minor] `alternative` is undefined for `levene` (scipy `levene` takes no alternative) and its interaction with `f_var` one-sided is spec'd but `ks2`'s is not.** Fix: state per-test: tests that ignore `alternative` echo `alternative="two-sided (forced)"` or ToolError on a non-default value.

**22. [ml, minor] `params_used` typed `dict[str,float]` for `cluster` can't be reused for `classify_eval`**, whose params include `kernel: str`. Fix: type `params_used: dict[str, float | str | int | None]` once in the schema section.

**23. [engmath, minor] `theorem_verified` semantics when `simplify` is inconclusive.** `simplify(L{f∗g} − F·G)` failing to reach 0 does not prove falsity. Fix: `True` on 0, `None` on non-zero-but-symbolic, and never `False` unless numerically refuted at sample points.

**24. [systems, minor] `default_t_end` undefined for marginal/unstable systems** (pole at origin → infinite slowest time constant; the design's own margin test uses 1/(s(s+1)(s+2))). Fix: spec the fallback: 7/|slowest *nonzero* Re(pole)|, else fixed 20.0 when all poles are on the axis.

**25. [systems, minor] `spectral_peaks(f_min_cpm=...)` value unspecified for the Hz lane** — geometry's 12 cpm default is meaningless for a 1 kHz-sampled tone. Fix: `f_min = 2/span` (first couple of non-DC bins), stated in the tool contract.

**26. [ml, minor] Feature-count test text self-contradicts (17 vs "exact count = ... = 19").** The arithmetic is 3+3+3+4+3+3 = 19. Fix: delete "17", assert `X.shape[1] == len(report.feature_names)` and `len == 19` for the full-group cylinder fixture.

**27. [stats §3.2, minor — verify only] `ply.bone_map_for` promotion is acyclic today** (`lbs.py` imports nothing from `ply`, verified), but it inverts layering — ply.py is currently the bottom module. Fix: import `lbs` lazily inside the function body so `ply`'s import cost/graph stays flat.

**28. [stats, minor] Sector test fixture is degenerate:** `n_sectors=16` against `make_cylinder(n_around=16)` gives exactly one vertex column per sector — each "sector profile" is a single generatrix line, so the Wilcoxon operates on maximally-noisy profiles. Fix: fixture `n_around=32`, or tool default `n_sectors=8` (matching `sector_profiles`' own default).

**29. [cross-pack, minor — tool selection] 35 total tools with two genuinely confusable pairs.** `compare_dump_ripples` (stats) vs `compare_geometry_signals` (geometry) both take two dumps + joint and both emit a ripple ratio; `fourier_series` (numeric mode) vs `sampling_check` vs `analyze_corrugation` all compute a spectrum of a 1-D series. Fix: mandatory cross-references in the docstrings ("descriptive deltas → compare_geometry_signals; statistical significance → compare_dump_ripples"; "harmonic decomposition → fourier_series; aliasing verdict → sampling_check"), and README documents the `DSP_TOOLSETS` trim as the intended mitigation for smaller clients.

**30. [netqueue, minor] `little_law` rejects legitimate zeros.** L=0/W=0 (empty system) is valid input when solving for the third quantity, and λ=0 is only invalid in a divisor slot. Fix: require λ>0 always; allow L/W ≥ 0; ToolError only on division by zero, naming the slot.

**31. [netqueue, minor] Two different instability strings.** The engine module raises `"unstable: rho=... (need mu > ... or servers >= ...)"` while the tool contract says error `"unstable queue: rho >= 1"` with the detail in the hint — "converts to ToolError verbatim" can't produce both. Fix: pin one split (error = `"unstable queue: rho=<v> >= 1"`, hint = the remedy clause) and make test 5 assert against it.

**32. [stats, minor] `kstest(y, name, args=params)` needs a positional tuple in `dist.shapes` order**, but `DistFit.params` is a `dict[str, float]`. Fix: `statskit.fit_candidates` keeps the raw fit tuple internally and builds the dict only for the report.

Everything else checked out: netqueue's M/M/4 and Erlang-B/C goldens, M/D/1 = half M/M/1 Lq, the SRTF/priority/paging/clock/Belady numbers, Banker's request tests 13-14, systems' step/Bode/margin goldens (ln 9, 16.3 %, 15.563 dB, 53.4°), engmath's residue/Fourier goldens, imaging's component geometry (areas/bboxes/centroids in `make_rects`), the 16-bit PNG round-trip against `load_image_gray`'s `I;16` handling, sklearn/sympy as pure wheels on bookworm-slim (sklearn wheels vendor libgomp — no Dockerfile change), and the os pack's `os_sim.py` stdlib-shadow avoidance.
